# 05 - 实施计划

## 1. 里程碑划分

按「先打通链路、再优化性能、最后加固」的顺序，分阶段交付，每个阶段都能独立验证。

### M0 — 项目骨架

- 初始化 cargo workspace，搭好模块结构
- `axum` 启动 HTTP 服务，托管一个静态 HTML 页面
- 浏览器能访问到页面
- **验证**：浏览器打开 `http://127.0.0.1:port` 看到页面

### M1 — WebSocket 通信 + 认证

- WebSocket 升级、握手、`hello` 消息
- 简单密码认证流程（先明文比较，后接 argon2）
- 会话状态机
- **验证**：浏览器连上 WebSocket，输错密码被拒，输对密码收到 `auth_ok`

### M2 — 输入注入（核心功能之一）

- `InputInjector` trait + `enigo` 实现
- 协议层解析 `input` 事件
- 键码映射表
- 输入注入线程
- **验证**：在浏览器页面（即便没有画面，用按钮/坐标输入框）发送鼠标移动、点击、按键，被控端真实响应

### M3 — 屏幕捕获 + 视频流（核心功能之二）

- `ScreenCapturer` trait + `scap` 实现
- `openh264` 编码
- BGRA→YUV 颜色转换
- 二进制视频帧协议
- 捕获/编码线程 + broadcast 分发
- 浏览器 WebCodecs 解码 + canvas 渲染
- **验证**：浏览器实时看到被控端画面，延迟可接受

### M4 — 端到端联调

- 输入坐标与画面对齐（归一化坐标换算）
- 关键帧策略、新连接起画
- 多浏览器同时连接
- TLS / wss 启用，自签名证书自动生成
- **验证**：完整远程控制体验 —— 看着画面操作，鼠标键盘准确响应

### M5 — 性能优化（按需）

- 捕获下沉：X11 SHM / Windows DXGI
- 硬件编码后端（FFmpeg VAAPI/NVENC/QSV）
- 帧率/码率自适应、背压处理
- 鼠标移动事件节流
- **验证**：高分辨率下 CPU 占用、延迟、帧率达标

### M6 — 安全加固

- argon2 密码哈希、暴力破解防护
- 会话超时、独占控制选项
- 安全提示日志
- **验证**：见 [04-安全设计.md](04-安全设计.md) 各项

### 预留 — Wayland 支持

- 接口在 M2/M3 已通过 trait 预留
- 后续实现 PipeWire 捕获 + uinput/portal 输入

## 2. 建议目录结构

```
RemoteControl/
├── Cargo.toml                  # workspace
├── docs/                       # 本设计文档
├── scripts/                    # 已有的安装脚本
├── crates/
│   └── server/                 # 被控端服务（第一阶段可只用单 crate）
│       ├── Cargo.toml
│       └── src/
│           ├── main.rs         # 入口、参数、配置
│           ├── config.rs       # 配置加载
│           ├── web.rs          # axum 路由、静态托管、ws 升级
│           ├── session.rs      # 会话/认证状态机
│           ├── protocol.rs     # 消息定义与编解码 (serde)
│           ├── capture/        # 屏幕捕获
│           │   ├── mod.rs      # ScreenCapturer trait + 工厂
│           │   ├── x11.rs      # #[cfg(linux + feature x11)]
│           │   ├── windows.rs  # #[cfg(windows)]
│           │   └── wayland.rs  # 预留，unimplemented
│           ├── encoder.rs      # 视频编码
│           ├── input/          # 输入注入
│           │   ├── mod.rs      # InputInjector trait + 工厂
│           │   ├── enigo_impl.rs
│           │   └── keymap.rs   # 键码映射表
│           └── pipeline.rs     # 捕获→编码→分发 线程编排
└── web/                        # 前端静态资源（编译进二进制或运行时托管）
    ├── index.html
    ├── app.js                  # ws 连接、输入采集、WebCodecs 解码渲染
    └── style.css
```

> 第一阶段不必拆多 crate，单个 `server` crate + 模块即可。等平台实现变多、想复用时再拆 `capture`/`input`/`protocol` 为独立 crate。

> 前端资源可用 `rust-embed` 在编译期打包进二进制，做到单文件分发；开发期也可从磁盘目录托管方便热改。

## 3. 配置文件示例（toml）

```toml
# config.toml
bind = "0.0.0.0:8443"
password = "change-me"          # 或 password_hash = "$argon2id$..."

[video]
fps = 30
bitrate = 4000000               # 4 Mbps
codec = "h264"

[security]
max_auth_failures = 5
auth_ban_seconds = 300
session_idle_timeout = 300
exclusive_control = false

[tls]
# 留空则自动生成自签名证书并缓存
# cert = "cert.pem"
# key  = "key.pem"
```

命令行参数覆盖配置文件，例如 `server --bind 127.0.0.1:8443 --password xxx`。

## 4. Cargo features 设计

用 feature 控制平台后端编译，避免在不相干平台拉无用依赖：

```toml
[features]
default = ["x11"]            # Linux 默认 x11
x11 = ["dep:x11rb", ...]
wayland = []                # 预留，暂空
# Windows 后端用 cfg(target_os) 自动启用，无需 feature
hw-encode = ["dep:ffmpeg-next"]   # 可选硬件编码
```

## 5. 关键技术风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| 软件 H.264 编码 CPU 占用高 | 高分辨率卡顿 | M5 切硬件编码；先降分辨率/帧率验证 |
| 端到端延迟偏高 | 操作迟滞 | 低延迟编码参数；WebCodecs 而非 MSE；后续评估 WebRTC |
| 键码映射不全 | 部分按键失效 | 映射表持续补充；记录未映射键日志 |
| 坐标错位 | 点击位置偏移 | 统一归一化坐标 + 服务端按真实分辨率换算 |
| `enigo` 在某平台行为差异 | 输入异常 | trait 抽象，必要时下沉到平台原生 API |
| 自签证书警告 | 用户体验 | 文档说明 + 提供 CA 导入指引 |
| 多屏/高 DPI | 捕获或坐标异常 | `screen_info` 暴露多屏信息，先支持单主屏，多屏后续迭代 |

## 6. 验证与测试策略

- **单元测试**：协议编解码、键码映射、坐标换算等纯逻辑。
- **集成测试**：起服务 + 模拟 ws 客户端，跑认证流程、输入事件解析。
- **手动联调**：M2/M3/M4 各阶段实机验证输入响应和画面。
- **跨平台验证**：X11 和 Windows 各跑一遍核心流程（Wayland 阶段暂不验证）。
- **性能基准**：测端到端延迟（输入→响应、画面延迟）、不同分辨率下 CPU 占用和帧率。
