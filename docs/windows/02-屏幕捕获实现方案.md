# Windows 屏幕捕获模块实现方案（Desktop Duplication API）

本文档详细描述使用 DXGI Desktop Duplication API 实现 Windows 屏幕捕获的技术方案。

## 一、技术概述

### 1.1 Desktop Duplication API 简介

Desktop Duplication API 是 Windows 8 引入的高性能屏幕捕获接口，属于 DirectX Graphics Infrastructure (DXGI) 的一部分。

**核心优势：**

| 特性 | 说明 |
|------|------|
| GPU 零拷贝 | 直接从 GPU 获取桌面合成后的纹理，无需 CPU 内存拷贝 |
| 脏区域支持 | API 返回屏幕变化区域，可优化传输（只传变化部分） |
| 光标内置 | API 直接提供光标位置和形状信息，无需额外捕获 |
| 帧同步 | 与桌面合成器同步，获取稳定的帧率 |

### 1.2 工作原理

```
┌─────────────────────────────────────────────────────────┐
│                    Windows Desktop Composition          │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                  │
│  │ App A   │  │ App B   │  │ Desktop │  ──→ DWM 合成    │
│  │ Window  │  │ Window  │  │  Icons  │                  │
│  └─────────┘  └─────────┘  └─────────┘                  │
│                          ↓                               │
│              ┌─────────────────────┐                     │
│              │  GPU Desktop Texture │ ← Desktop Duplication 访问此处 │
│              └─────────────────────┘                     │
└─────────────────────────────────────────────────────────┘
                           ↓
              ┌─────────────────────┐
              │   AcquireNextFrame   │ ← 获取帧 + 脏区域 + 光标信息
              └─────────────────────┘
                           ↓
              ┌─────────────────────┐
              │   GPU → CPU Copy    │ ← 映射纹理到内存
              └─────────────────────┘
                           ↓
              ┌─────────────────────┐
              │   BGRA 像素数据      │ ← 输出到编码器
              └─────────────────────┘
```

### 1.3 适用条件

| 条件 | 要求 |
|------|------|
| 操作系统 | Windows 8 / 8.1 / 10 / 11 |
| 显卡 | 支持 DirectX 11 的显卡（2010 年后基本都支持） |
| 显示器 | 必须有活动的显示器输出 |
| 会话类型 | 本地会话或特定远程会话（普通 RDP 会话不支持） |

## 二、API 核心对象

### 2.1 对象层次结构

```
IDXGIFactory1          → DXGI 工厂，用于枚举适配器
    ↓
IDXGIAdapter1          → 显卡适配器
    ↓
IDXGIOutput1           → 显示器输出
    ↓
IDXGIOutputDuplication → 桌面复制对象（核心捕获接口）
```

### 2.2 关键接口方法

**IDXGIOutputDuplication 核心方法：**

| 方法 | 功能 |
|------|------|
| `AcquireNextFrame` | 获取下一帧桌面内容 |
| `GetFrameDirtyRects` | 获取本帧变化的区域列表 |
| `GetFramePointerShape` | 获取光标形状像素数据 |
| `ReleaseFrame` | 释放帧，准备获取下一帧 |
| `GetDesc` | 获取输出描述（分辨率、旋转等） |

**AcquireNextFrame 返回的帧信息：**

| 字段 | 说明 |
|------|------|
| `AccumulatedFrames` | 累积帧数（判断是否有新帧） |
| `LastPresentTime` | 上次呈现时间戳 |
| `PointerPosition` | 光标位置（visible、position） |
| `PointerShapeBufferSize` | 光标形状缓冲区大小（0 表示无变化） |

## 三、初始化流程

### 3.1 流程步骤

```
Step 1: 创建 D3D11 Device
        ↓
Step 2: 获取 DXGI Device
        ↓
Step 3: 获取 DXGI Factory
        ↓
Step 4: 枚举适配器（显卡）
        ↓
Step 5: 枚举输出（显示器）
        ↓
Step 6: 创建 OutputDuplication
        ↓
Step 7: 获取输出描述（分辨率）
```

### 3.2 各步骤详解

**Step 1: 创建 D3D11 Device**

- 使用 `D3D11CreateDevice` 创建设备
- 需要指定 `D3D_DRIVER_TYPE_HARDWARE` 使用硬件加速
- Feature Level 选择 `D3D11_FEATURE_LEVEL_11_0` 或更低以保证兼容性

**Step 2-3: 获取 DXGI 接口**

- 从 D3D11 Device 通过 `QueryInterface` 获取 `IDXGIDevice`
- 再获取 `IDXGIFactory1`

**Step 4: 枚举适配器**

- 使用 `EnumAdapters1` 遍历所有显卡
- 通常选择第一个适配器（主显卡）
- 如果多个显卡都有输出，需要为每个适配器创建 duplication

**Step 5: 枚举输出**

- 使用 `EnumOutputs` 遍历适配器的所有显示器输出
- 每个显示器对应一个 `IDXGIOutput1`
- 需要记录每个输出的位置坐标（用于多显示器拼接）

**Step 6: 创建 OutputDuplication**

```text
调用 IDXGIOutput1::DuplicateOutput(ID3D11Device)
返回 IDXGIOutputDuplication 对象
```

**注意：** 每个输出只能创建一个 duplication 对象。如果其他程序（如录屏软件）已占用，会返回 `DXGI_ERROR_ACCESS_DENIED`。

**Step 7: 获取输出描述**

调用 `GetDesc` 获取：
- `Width` / `Height`：分辨率
- `Rotation`：显示器旋转角度（0°/90°/180°/270°）
- `DesktopCoordinates`：在 Virtual Screen 中的位置

## 四、抓帧流程

### 4.1 单帧捕获流程

```
Step 1: AcquireNextFrame(timeout)
        ↓ (等待新帧)
Step 2: 检查 AccumulatedFrames > 0
        ↓ (有新帧)
Step 3: 获取帧纹理 (GetFrameTexture)
        ↓
Step 4: 创建 staging texture（CPU 可访问）
        ↓
Step 5: CopyResource 到 staging texture
        ↓
Step 6: Map staging texture 获取像素指针
        ↓
Step 7: 拷贝像素数据到 Vec<u8>
        ↓
Step 8: Unmap staging texture
        ↓
Step 9: ReleaseFrame
```

### 4.2 关键步骤详解

**Step 1: AcquireNextFrame**

- 参数 `TimeoutInMilliseconds`：等待时间
  - `0`：立即返回（轮询模式）
  - `500`：等待 500ms（推荐，避免空转）
  - `INFINITE`：无限等待
- 返回 `DXGI_OUTDUPL_FRAME_INFO` 结构体

**Step 3: 获取帧纹理**

- 帧纹理是 `ID3D11Texture2D`
- 需要通过 `QueryInterface` 从帧资源获取

**Step 4-6: 映射到 CPU**

Desktop Duplication 返回的纹理是 GPU 纹理，CPU 无法直接访问。需要：

1. 创建一个 **staging texture**（`D3D11_USAGE_STAGING`，`D3D11_CPU_ACCESS_READ`）
2. 使用 `CopyResource` 将 GPU 纹理拷贝到 staging texture
3. 使用 `Map` 映射 staging texture 获取像素指针

**纹理格式：**

Desktop Duplication 返回的格式通常是：
- `DXGI_FORMAT_B8G8R8A8_UNORM`（BGRA，与 X11 对齐）
- `DXGI_FORMAT_R10G10B10A2_UNORM`（HDR 显示器可能使用）
- `DXGI_FORMAT_R16G16B16A16_FLOAT`（HDR 显示器）

如果不是 BGRA 格式，需要转换。

**Step 7: 拷贝数据**

- 从 mapped 指针读取像素数据
- 行可能有 padding（`RowPitch` 可能大于 `Width * 4`）
- 需要逐行拷贝，跳过 padding

```text
for row in 0..height:
    src = mapped_ptr + row * row_pitch
    dst = output_vec + row * width * 4
    copy(src, dst, width * 4)
```

**Step 9: ReleaseFrame**

- 必须调用 `ReleaseFrame` 释放帧，否则无法获取下一帧
- 在释放前完成所有像素拷贝操作

### 4.3 无新帧的处理

当 `AcquireNextFrame` 超时返回且 `AccumulatedFrames == 0`：

| 策略 | 说明 |
|------|------|
| 返回上一帧 | 编码器需要持续输入帧，可缓存上一帧重复使用 |
| 返回空/跳过 | 通知编码器无变化，可能产生空帧问题 |

**推荐：** 缓存上一帧，无新帧时返回缓存的帧。

## 五、光标捕获

### 5.1 光标信息获取

Desktop Duplication API 在 `AcquireNextFrame` 返回的 `DXGI_OUTDUPL_FRAME_INFO` 中包含光标信息：

| 字段 | 说明 |
|------|------|
| `PointerPosition.Visible` | 光标是否可见 |
| `PointerPosition.Position` | 光标坐标（桌面坐标系） |
| `PointerShapeBufferSize` | 光标形状缓冲区大小（> 0 表示形状变化） |

### 5.2 光标形状获取

当 `PointerShapeBufferSize > 0` 时，调用 `GetFramePointerShape` 获取形状：

**输入参数：**
- `BufferSize`：缓冲区大小（从 frame info 获取）
- `pBuffer`：接收像素数据的缓冲区

**返回信息：**
- `Type`：光标类型
  - `DXGI_OUTDUPL_POINTER_SHAPE_TYPE_MONOCHROME`：单色光标
  - `DXGI_OUTDUPL_POINTER_SHAPE_TYPE_COLOR`：彩色光标
  - `DXGI_OUTDUPL_POINTER_SHAPE_TYPE_MASKED_COLOR`：遮罩彩色光标
- `Width` / `Height`：光标尺寸
- `Pitch`：行间距
- `HotSpot`：热点坐标

### 5.3 光标像素格式处理

不同类型的光标需要不同的处理方式：

**Type = COLOR（最常见）：**
- 直接是 RGBA 或 BGRA 格式
- 通常 `Pitch = Width * 4`
- 可直接使用或转换格式

**Type = MASKED_COLOR：**
- 包含颜色数据和遮罩
- 需要根据遮罩计算最终像素

**Type = MONOCHROME：**
- 1-bit 单色位图
- 需要展开为 RGBA 格式

**推荐处理：** 只处理 `COLOR` 类型，其他类型返回 None 或默认光标。

### 5.4 光标状态缓存

光标形状变化时 API 才会返回 `PointerShapeBufferSize > 0`，需要缓存：

| 缓存内容 | 说明 |
|---------|------|
| 当前光标形状 | `CursorShape` 结构体 |
| 光标序列号 | 用于前端判断是否需要更新 |
| 上次形状大小 | 判断是否需要重新获取 |

**逻辑：**

```
每次 AcquireNextFrame:
    if PointerShapeBufferSize > 0:
        调用 GetFramePointerShape 获取新形状
        更新缓存
        递增序列号
    else:
        使用缓存的形状（如果存在）
```

### 5.5 与 X11 实现对齐

X11 的 XFIXES 返回的是 ARGB 预乘 alpha 格式，需要转换为未预乘。

Desktop Duplication 的 `COLOR` 类型通常是未预乘 alpha，可直接使用。

**输出格式对齐：**

| 项目 | X11 格式 | Windows 格式 | 需转换 |
|------|---------|-------------|--------|
| 像素顺序 | RGBA | BGRA 或 RGBA | 可能需要 |
| Alpha | 未预乘 | 通常未预乘 | 通常不需要 |

## 六、分辨率变化处理

### 6.1 分辨率变化的检测

Desktop Duplication API 在以下情况会失效：
- 分辨率改变
- 显示器断开/连接
- 显示器旋转
- 桌面模式切换（如进入全屏游戏）

**检测方式：**

调用 `AcquireNextFrame` 时可能返回错误码：
- `DXGI_ERROR_ACCESS_LOST`：访问丢失，需要重新创建 duplication

### 6.2 重新初始化流程

当检测到 `DXGI_ERROR_ACCESS_LOST`：

```
Step 1: 释放旧的 OutputDuplication
        ↓
Step 2: 重新枚举输出（可能有显示器增减）
        ↓
Step 3: 重新创建 OutputDuplication
        ↓
Step 4: 获取新的描述（分辨率）
        ↓
Step 5: 重新创建 staging texture（尺寸可能变化）
```

### 6.3 与 ScreenCapturer trait 对齐

`refresh_info()` 方法需要：

| 行为 | 说明 |
|------|------|
| 检测分辨率变化 | 比较当前分辨率与缓存值 |
| 返回 `Ok(true)` | 表示分辨率已变化，上层需要重新初始化编码器 |
| 返回 `Ok(false)` | 表示分辨率未变化 |

**实现方式：**

定期调用 `GetDesc` 获取当前分辨率，与缓存值比较。或在 `AcquireNextFrame` 返回错误时触发重新初始化。

## 七、多显示器支持

### 7.1 多显示器架构

Windows 使用 **Virtual Screen** 坐标系：
- 主显示器左上角为原点 (0, 0)
- 其他显示器根据相对位置有正/负坐标

**示例布局：**

```
Virtual Screen 坐标系:

         (-1920, 0)        (0, 0)           (1920, 0)
            ↓                 ↓                 ↓
    ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
    │  Monitor 2  │   │  Monitor 1  │   │  Monitor 3  │
    │  (副显示器)  │   │  (主显示器)  │   │  (副显示器)  │
    │  1920x1080  │   │  1920x1080  │   │  1920x1080  │
    └─────────────┘   └─────────────┘   └─────────────┘

Virtual Screen 总范围: (-1920, 0) 到 (3840, 1080)
总宽度: 3840 (三个显示器宽度之和)
```

### 7.2 Desktop Duplication 多显示器处理

Desktop Duplication API 的限制：
- 每个 `IDXGIOutputDuplication` 只能捕获一个显示器
- 需要为每个显示器创建独立的 duplication 对象

**方案一：捕获单个显示器（推荐初期实现）**

| 项目 | 说明 |
|------|------|
| 默认捕获 | 主显示器（第一个输出） |
| 配置扩展 | 后续可支持配置指定显示器 |

**方案二：捕获所有显示器（完整多显示器支持）**

| 步骤 | 说明 |
|------|------|
| 1 | 为每个输出创建 `OutputDuplication` |
| 2 | 分别获取每帧，记录各显示器的脏区域 |
| 3 | 拼接为一张完整的 Virtual Screen 图像 |
| 4 | 或只传变化区域的增量 |

**拼接实现：**

```
创建大图: total_width × max_height (BGRA)
for each monitor:
    获取帧纹理
    计算该显示器在 Virtual Screen 中的位置
    将像素拷贝到大图的对应位置
```

### 7.3 实现建议

| 阶段 | 实现 |
|------|------|
| 第一阶段 | 只捕获主显示器（单显示器场景） |
| 第二阶段 | 添加多显示器拼接支持 |

## 八、错误处理

### 8.1 常见错误码

| 错误码 | 原因 | 处理方式 |
|--------|------|---------|
| `DXGI_ERROR_ACCESS_LOST` | 分辨率变化/显示器断开 | 重新初始化 |
| `DXGI_ERROR_ACCESS_DENIED` | 其他程序已占用 duplication | 提示用户关闭录屏软件 |
| `DXGI_ERROR_UNSUPPORTED` | 不支持 duplication | 降级到 GDI 方案 |
| `DXGI_ERROR_DEVICE_REMOVED` | 显卡设备丢失 | 重新创建 Device |
| `E_ACCESSDENIED` | 权限问题 | 检查会话类型 |

### 8.2 错误恢复策略

| 错误类型 | 恢复策略 |
|---------|---------|
| Access Lost | 自动重新初始化，通知上层分辨率变化 |
| Access Denied | 提示用户，等待用户处理 |
| Unsupported | 降级到 GDI BitBlt 方案 |
| Device Removed | 重新创建整个 D3D11 Device |

### 8.3 与 trait 返回值对齐

ScreenCapturer trait 的 `grab_frame()` 返回 `Result<Frame>`：

| 错误类型 | 返回值 |
|---------|--------|
| 可恢复（如暂时无帧） | 返回上一帧（缓存） |
| 需重新初始化 | 返回 `Error`，上层调用 `refresh_info` |
| 不可恢复 | 返回 `Error`，服务停止 |

## 九、性能优化

### 9.1 利用脏区域

Desktop Duplication 返回的帧包含 `DirtyRects`（变化区域列表）：

| 优化方式 | 说明 |
|---------|------|
| 增量传输 | 只传输变化区域的像素 |
| 帧判断 | 无脏区域时可跳过编码 |
| ROI 编码 | 只编码变化区域（需编码器支持） |

**脏区域获取：**

调用 `GetFrameDirtyRects` 获取 `RECT` 数组。

**实现建议：** 初期可忽略脏区域，后续优化时利用。

### 9.2 帧率控制

| 策略 | 说明 |
|------|------|
| Timeout 参数 | `AcquireNextFrame(500)` 等待最多 500ms |
| 帧率上限 | 上层 pipeline 已有帧率控制（config.toml） |
| 避免空转 | 无帧时不要频繁轮询（Timeout=0） |

### 9.3 内存复用

| 优化点 | 方式 |
|-------|------|
| Staging Texture | 尺寸不变时复用，不重新创建 |
| 像素 Vec<u8> | 预分配足够容量，避免每次 realloc |
| 光标缓存 | 形状不变时复用缓存 |

### 9.4 线程模型

与 X11 实现对齐：`ScreenCapturer` 需要实现 `Send` trait。

| 要求 | 说明 |
|------|------|
| D3D11 Device | 单线程使用，`Send` 安全 |
| OutputDuplication | 单线程使用，需确保 `Send` |

**windows-rs 的 COM 对象默认不是 Send，需要包装：**

使用 `unsafe impl Send` 包装结构体，确保不会跨线程共享。

## 十、与现有代码对接

### 10.1 结构体定义

```rust
// capture/windows.rs

pub struct WindowsCapturer {
    // D3D11 设备
    device: ID3D11Device,
    // 设备上下文
    context: ID3D11DeviceContext,
    // 桌面复制对象
    duplication: IDXGIOutputDuplication,
    // staging 纹理（CPU 可访问）
    staging_texture: Option<ID3D11Texture2D>,
    // 屏幕信息
    info: ScreenInfo,
    // 上一帧缓存（用于无新帧时）
    last_frame: Option<Frame>,
    // 光标形状缓存
    cursor_cache: Option<CursorShape>,
    // 显示器在 Virtual Screen 中的偏移
    offset_x: i32,
    offset_y: i32,
}
```

### 10.2 实现 ScreenCapturer trait

| 方法 | 实现要点 |
|------|---------|
| `info()` | 返回缓存的 `ScreenInfo` |
| `grab_frame()` | AcquireNextFrame → Copy → Map → 拷贝 → Release |
| `refresh_info()` | 检测 Access Lost，重新初始化，返回是否变化 |
| `get_cursor_shape()` | 返回光标缓存 |

### 10.3 像素格式保证

确保输出格式与 X11 一致：

| 项目 | 要求 |
|------|------|
| 格式 | BGRA（B 在最低地址） |
| 字节序 | 小端序 |
| 尺寸 | `width * height * 4` 字节 |

### 10.4 工厂函数更新

```rust
// capture/mod.rs

#[cfg(target_os = "windows")]
{
    let capturer = windows::WindowsCapturer::new()?;

}
```

## 十三、风险与对策

| 风险 | 对策 |
