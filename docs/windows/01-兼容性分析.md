# Windows 兼容性分析报告

本文档分析将 RemoteControl 项目移植到 Windows 平台所需的工作内容。

## 当前状态

项目已有良好的跨平台设计框架：
- 使用 `trait` 抽象平台功能（`ScreenCapturer`、`InputInjector`）
- 使用 `#[cfg(target_os = "windows")]` 条件编译
- 但 **Windows 模块文件尚未实现**

---

## 需要完善的内容

### 1. 屏幕捕获模块 (`capture/windows.rs`)

需要使用 Windows API 实现：

| 功能 | 推荐方案 | Windows API / Crate |
|------|----------|---------------------|
| 屏幕截图 | DXGI Desktop Duplication | `windows` crate 的 `Windows::Graphics::Capture` |
| 获取显示器信息 | EnumDisplayMonitors | `windows::Win32::Graphics::Gdi` |
| 获取光标形状 | GetCursorInfo + DrawIcon | `windows::Win32::UI::WindowsAndMessaging` |
| 性能优化 | GPU 硬件加速 | DirectX 11/12 |

**关键实现点：**
```rust
// 需要实现 trait 方法：
pub trait ScreenCapturer: Send {
    fn info(&self) -> ScreenInfo;
    fn grab_frame(&mut self) -> Result<Frame>;
    fn refresh_info(&mut self) -> Result<bool>;
    fn get_cursor_shape(&self) -> Result<Option<CursorShape>>;
}
```

**推荐依赖：**
```toml
[target.'cfg(windows)'.dependencies]
windows = { version = "0.58", features = [
    "Win32_Foundation",
    "Win32_Graphics_Gdi",
    "Win32_Graphics_Direct3D11",
    "Win32_Graphics_Dxgi",
    "Win32_UI_WindowsAndMessaging",
    "Graphics_Capture",
]}
```

---

### 2. 输入注入模块 (`input/windows.rs`)

| 功能 | Windows API | 说明 |
|------|-------------|------|
| 鼠标移动/点击 | `SendInput` | `INPUT_MOUSE` 类型 |
| 滚轮注入 | `SendInput` | `MOUSEEVENTF_WHEEL` |
| 键盘注入 | `SendInput` | `INPUT_KEYBOARD` 类型 |
| 键盘映射 | `MapVirtualKey` | Web code → Windows VK 码 |

**关键实现点：**
```rust
pub trait InputInjector: Send {
    fn move_mouse(&mut self, x: i32, y: i32) -> Result<()>;
    fn mouse_button(&mut self, btn: MouseButton, pressed: bool) -> Result<()>;
    fn scroll(&mut self, dx: i32, dy: i32) -> Result<()>;
    fn key(&mut self, code: &str, pressed: bool) -> Result<()>;
}
```

**键盘映射表需要扩展：**
- 当前 `keymap.rs` 仅处理标准键
- Windows 需要映射到 Virtual Key Codes
- 可使用 `enigo` crate 的 Windows 后端（它已支持跨平台）

---

### 3. 剪切板模块 (`clipboard.rs`)

**好消息：** 使用 `arboard` crate，**已跨平台兼容** ✅

只需确保 Cargo.toml 中 Windows 平台的依赖配置：
```toml
[target.'cfg(windows)'.dependencies]
arboard = "3.4"  # 已有，无需修改
```

---

### 4. 部署和运行脚本 (`scripts/`)

当前脚本全是 Shell 脚本，需要 Windows 等效实现：

| Linux 脚本 | Windows 需求 |
|-----------|-------------|
| `build.sh` | `build.ps1` 或 `build.bat` |
| `start-daemon.sh` | Windows 服务注册或后台启动 |
| `stop-daemon.sh` | 进程终止脚本 |
| `install-autostart.sh` | 注册表启动项或任务计划程序 |

**自启动方案对比：**

| 平台 | 当前方案 | Windows 方案 |
|------|----------|-------------|
| Linux | systemd user service | 注册表 `HKCU\Run` / Task Scheduler |

---

### 5. 配置文件路径 (`config.rs`)

需要处理平台差异：

```rust
// 当前可能的硬编码路径需要检查
fn get_config_path() -> PathBuf {
    #[cfg(target_os = "linux")]
    { dirs::config_dir().unwrap().join("remote-control/config.toml") }

    #[cfg(target_os = "windows")]
    { dirs::config_dir().unwrap().join("RemoteControl\\config.toml") }
}
```

---

### 6. TLS 证书存储位置 (`tls.rs`)

证书缓存路径需要平台适配：
- Linux: `~/.local/share/remote-control/certs/` 或 `~/.cache/...`
- Windows: `%APPDATA%\RemoteControl\certs\`

---

### 7. 依赖配置 (`Cargo.toml`)

需要添加条件依赖：

```toml
[target.'cfg(target_os = "linux")'.dependencies]
x11rb = "0.13"

[target.'cfg(target_os = "windows")'.dependencies]
windows = { version = "0.58", features = [...] }
# 或者使用现成的跨平台抽象库：
# xcap = { version = "0.0.10" }  # 跨平台屏幕捕获
```

**可选方案：** 使用 `enigo` crate（已在用），它已支持 Windows 输入注入。

---

### 8. 潜在的其他问题

| 问题 | 说明 | 建议 |
|------|------|------|
| DPI 缩放 | Windows 高 DPI 显示器坐标可能错位 | 调用 `SetProcessDPIAware` |
| 多显示器 | Windows 多显示器坐标系统不同 | 使用 virtual screen coordinates |
| UAC 提权 | 输入注入可能需要管理员权限 | 应用清单配置或用户授权 |
| 文件锁 | Windows 文件锁定机制不同 | 注意配置文件读写锁定 |

---

## 实现优先级建议

### 第一阶段（核心功能）
1. **屏幕捕获** - 使用 `windows` crate 的 Desktop Duplication API
2. **输入注入** - 使用 `enigo` crate（已有 Windows 后端）或直接 `SendInput`
3. **键盘映射** - 扩展 `keymap.rs` 支持 Windows VK 码

### 第二阶段（部署运维）
4. PowerShell 部署脚本
5. Windows 服务注册
6. 开机自启动

### 第三阶段（优化）
7. 硬件加速编码（可选）
8. DPI 感知
9. 多显示器支持

---

## 快速启动方案（如果使用现有库）

如果想快速实现，可以考虑：

```toml
# 跨平台屏幕捕获
[target.'cfg(windows)'.dependencies]
xcap = "0.0.10"  # 跨平台屏幕截图库

# 输入注入 - enigo 已支持跨平台
# 当前已在用
```

`xcap` 是一个跨平台的屏幕捕获库，支持 Windows/Linux/macOS，可以快速实现屏幕捕获功能。
