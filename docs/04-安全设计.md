# 04 - 安全设计

远程控制是高危能力：一旦被未授权访问，攻击者就拥有了被控电脑的完整鼠标键盘控制权，等同于物理坐在电脑前。即便是「简单密码」场景，传输加密和基本防护也不能省。

本方案的安全目标定位为**个人/可信局域网使用**，用简单密码认证 + 传输加密，但架构上为后续加固预留空间。

## 1. 威胁模型

| 威胁 | 说明 | 应对 |
| --- | --- | --- |
| 窃听 | 局域网内抓包获取画面/输入/密码 | TLS 加密整条 WebSocket（wss） |
| 未授权访问 | 任何人打开页面就能控制 | 密码认证，认证前不推流不接收输入 |
| 密码暴力破解 | 反复猜密码 | 失败次数限制 + 指数退避 |
| 会话劫持 | 窃取会话凭证冒充 | 短期会话 token + TLS 防窃听 |
| 重放攻击 | 重放认证消息 | TLS 已防重放；token 一次性/带时效 |

不在本阶段范围（个人局域网场景）：DDoS 防护、多租户隔离、审计合规等企业级需求，但架构不阻碍后续添加。

## 2. 传输加密（TLS / wss）

**强制使用 wss（WebSocket over TLS）**，不提供明文 ws。

- 用 `rustls`（纯 Rust，无系统 OpenSSL 依赖）。
- 局域网场景没有公网域名，无法用 Let's Encrypt。方案：
  - **首次启动用 `rcgen` 自动生成自签名证书**，保存到配置目录复用。
  - 浏览器首次访问会警告「证书不受信任」，用户手动信任即可（局域网自签场景常态）。
  - 进阶可选：把生成的 CA 证书导出，让用户导入系统/浏览器信任库，消除警告。

> 为什么不省略 TLS：没有 TLS，局域网内任何人抓包就能拿到明文密码和全部屏幕画面、按键内容（包括用户在被控端输入的其它密码）。这是不可接受的泄露面。

## 3. 密码认证流程

### 3.1 密码存储

- 服务端不明文存密码。启动时读取配置中的密码，在内存中用 `argon2` 哈希；或配置文件里直接存哈希值。
- 即使是「简单密码」，也用哈希比较，避免日志/内存 dump 泄露明文。

### 3.2 认证流程

```
1. WebSocket 建立（已在 TLS 之上）
2. 服务端发 hello (auth_required: true)
3. 浏览器提交 { type:"auth", token: "<用户输入的密码>" }
4. 服务端用 argon2 校验密码哈希
   ├─ 通过: 生成会话，回 auth_ok + session_id，开始推流
   └─ 失败: 回 auth_fail，记录失败次数
5. 连续失败 N 次 → 该来源 IP 进入退避/封禁窗口
```

### 3.3 会话管理

认证通过后，服务端为连接分配会话状态：

```rust
struct Session {
    id: Uuid,
    peer_addr: SocketAddr,
    authenticated_at: Instant,
    last_active: Instant,
}
```

- 会话与 WebSocket 连接绑定，连接断开即销毁会话。
- 空闲超时：长时间无任何消息（含心跳）自动断开，要求重新认证。
- 认证状态是连接级别的状态机：`Unauthenticated → Authenticated`，未认证状态下丢弃所有输入和控制消息。

## 4. 暴力破解防护

简单但有效的措施：

- **失败计数 + 指数退避**：按来源 IP 记录认证失败次数，失败后强制延迟响应（如 1s、2s、4s…），N 次后临时封禁。
- **延迟响应**：认证失败时固定延迟一小段时间再回复，削弱时序侧信道并拖慢爆破。
- **常数时间比较**：密码/哈希比较用常数时间算法（`argon2` 校验本身满足），避免时序攻击。

## 5. 输入授权边界

- 认证前：服务端**绝不**注入任何输入、**绝不**推送任何画面。
- 多连接：默认所有已认证连接都可发送输入（个人场景）。预留配置项 `exclusive_control`，开启后只有第一个认证连接可控制，其余只能观看。

## 6. 绑定地址与暴露面

- 默认监听地址建议明确，文档提示用户：
  - 仅本机调试：`127.0.0.1`
  - 局域网使用：`0.0.0.0` 或指定网卡 IP
- **不建议直接暴露到公网**。若需公网访问，应走 VPN 或反向代理 + 更强认证（超出本阶段）。启动时若监听 `0.0.0.0` 可打印一条安全提示日志。

## 7. 安全相关配置项

| 配置 | 说明 | 默认 |
| --- | --- | --- |
| `password` | 访问密码（或其哈希） | 必填，无默认 |
| `bind` | 监听地址 | `0.0.0.0:port` |
| `tls_cert` / `tls_key` | TLS 证书路径 | 不填则自动生成自签名 |
| `max_auth_failures` | 封禁前最大失败次数 | 5 |
| `auth_ban_seconds` | 封禁时长 | 300 |
| `session_idle_timeout` | 会话空闲超时（秒） | 300 |
| `exclusive_control` | 是否独占控制 | false |

## 8. 风险提示（交付时需明确告知用户）

1. 自签名证书会触发浏览器警告，需手动信任 —— 这是局域网无域名的固有限制。
2. 「简单密码」强度依赖用户设置，弱密码仍可能被爆破，建议设置足够复杂的密码。
3. 本方案为局域网/可信网络设计，**不应未经加固直接暴露到公网**。
4. 被控端运行服务的进程拥有当前登录用户的全部输入权限，应以合适权限运行，避免以高权限（root/管理员）长期驻留。
